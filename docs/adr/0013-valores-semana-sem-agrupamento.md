# Exibir valores da semana sem ordem agrupada, consultando `ordem_pagamento` direto

**Contexto:** quando o cadastro bancário do favorecido não existe no momento em que `P_AGRUPAR_ORDENS` roda, o item "é ignorado até serem preenchidos" (CONTEXT.md, `ClienteFavorecido`) — a captura fica em `ordem_pagamento` com `ordemPagamentoAgrupadoId IS NULL` para sempre (a janela daquele agrupamento não roda de novo). O endpoint `GET ordem-pagamento/semanal` (`findOrdensPagamentoAgrupadasByOrdemPagamentoAgrupadoId`) exige um `ordemPagamentoAgrupadoIds` e faz `INNER JOIN ordem_pagamento_agrupado`, então não existe forma de ver o detalhamento diário dessa semana — nem a tela admin (Permissionário → Detalhes) nem "Meu Extrato" conseguem abrir o drill-down (confirmado em staging: permissionária #3478, semana de 23/10/2026, `ordemPagamentoAgrupadoIds: null`).

**Decisão:** criar um caminho alternativo (`GET ordem-pagamento/semanal-sem-agrupamento`) que recebe `userId` + a data da tentativa de pagamento (a mesma usada hoje como `endDate`) em vez de um id de agrupamento, reaproveita o cálculo de janela já existente (`subDays`/`isFriday`/`isTuesday`, o mesmo de `findOrdensPagamentoAgrupadasByOrdemPagamentoAgrupadoId`) e consulta `ordem_pagamento` diretamente por `userId` + intervalo de `dataCaptura`, filtrando `ordemPagamentoAgrupadoId IS NULL`, sem o `INNER JOIN` em `ordem_pagamento_agrupado`. O retorno usa o mesmo `OrdemPagamentoSemanalDto[]` da rota existente, para o front-end reusar a mesma tabela "Valores da semana"/`Table.js` sem um formato novo.

**Por que não** alterar `P_AGRUPAR_ORDENS` para rodar retroativamente quando o cadastro bancário chega depois: seria uma mudança no pipeline de pagamento (`src/cnab/`, dado sensível, área em desenvolvimento ativo) só para resolver uma tela de visualização; o requisito aqui é mostrar o valor com aviso de pendência, não paga-lo — não há necessidade de criar a ordem agrupada de verdade.
